# Vision and Presence Detection Module

Module 2 for the Vision and Presence Detection module.

This module converts the robot face-detection output into a structured user-state topic. It reports visual evidence only. It does not decide fatigue, manage sessions, parse voice commands, or speak through `SoundClient`.

## 1. What This Module Does

Input:

```text
/face_detection/faces
opencv_apps/FaceArrayStamped
```

Output:

```text
Topic name:   /vision_and_presence_detection
Message type: rchomeedu_vision/UserState
```

Important distinction:

```text
/vision_and_presence_detection
```

is the ROS topic name. It is the runtime communication channel that downstream modules subscribe to.

```text
rchomeedu_vision/UserState
```

is the ROS message type. It is generated by catkin from `msg/UserState.msg` after `catkin_make`.

The topic name comes from the module name `Vision and Presence Detection`. ROS topic names cannot contain spaces, so the valid lowercase topic is `/vision_and_presence_detection`.

Processing:

```text
face_detection output
-> faces_exist / eyes_exist
-> UserStateLogic
-> /vision_and_presence_detection
```

State fields:

```text
bool user_present
int32 consecutive_eyes_missing
int32 consecutive_face_absent
time stamp
```

Field meaning:

| Field | Meaning |
|---|---|
| `user_present` | True when a face is currently detected |
| `consecutive_eyes_missing` | Consecutive callbacks where face exists but eyes are not detected |
| `consecutive_face_absent` | Consecutive callbacks where no face is detected |
| `stamp` | ROS timestamp for this state update |

Phase 8 head posture should be published separately as:

```text
Topic name:   /head_posture_state
Message type: rchomeedu_vision/HeadPostureState
```

Do not put head-posture logic into `UserStateLogic`. This module stays focused on face/eye presence. The fatigue monitor combines `/vision_and_presence_detection` and `/head_posture_state`.

## 4. Robot Package Setup

Use the existing robot package:

```text
rchomeedu_vision
```

This matches the original `say_hello_ans.py` instruction, where scripts and launch files are placed under:

```text
~/catkin_ws/src/rc-home-edu-learn-ros/rchomeedu_vision/scripts
~/catkin_ws/src/rc-home-edu-learn-ros/rchomeedu_vision/launch
```

The ROS scripts import:

```python
from rchomeedu_vision.msg import UserState
```

This Python module is not manually written. It is generated automatically by catkin from:

```text
rchomeedu_vision/msg/UserState.msg
```

after:

```bash
catkin_make
source devel/setup.bash
```

So a local Mac IDE warning such as `Cannot find module rchomeedu_vision.msg` is expected before the file is deployed into the robot's catkin workspace and built. It is not a logic error.

Important: this project folder does not need its own `CMakeLists.txt` or `package.xml` if you deploy into the existing `rchomeedu_vision` package. You only need to modify the existing `rchomeedu_vision/CMakeLists.txt` and `rchomeedu_vision/package.xml` on the robot.

If you later decide to turn this folder itself into a standalone catkin package, then you would add a root-level `CMakeLists.txt` and `package.xml`. For the current workflow, do not create duplicate package files here.

Create the `msg` folder if it does not already exist:

```bash
mkdir -p ~/catkin_ws/src/rc-home-edu-learn-ros/rchomeedu_vision/msg
```

Copy Module 2 files:


Make sure Python files use Unix/Linux line endings.

## 5. Message Build Config

`UserState.msg` must be registered in the existing `rchomeedu_vision/CMakeLists.txt` and `rchomeedu_vision/package.xml`. If Phase 8 head posture is included, register `HeadPostureState.msg` in the same message block.

This step is what creates the generated Python import used by the ROS scripts:

```python
from rchomeedu_vision.msg import UserState
from rchomeedu_vision.msg import HeadPostureState
```

Without this step, the IDE and the robot runtime will not be able to find `rchomeedu_vision.msg`.

In `package.xml`, make sure these dependencies exist. Do not duplicate entries if `rchomeedu_vision` already has them:

```xml
<buildtool_depend>catkin</buildtool_depend>

<build_depend>rospy</build_depend>
<build_depend>std_msgs</build_depend>
<build_depend>opencv_apps</build_depend>
<build_depend>message_generation</build_depend>

<exec_depend>rospy</exec_depend>
<exec_depend>std_msgs</exec_depend>
<exec_depend>opencv_apps</exec_depend>
<exec_depend>message_runtime</exec_depend>
```

In `CMakeLists.txt`, the key blocks are:

```cmake
find_package(catkin REQUIRED COMPONENTS
  rospy
  std_msgs
  opencv_apps
  message_generation
)

add_message_files(
  FILES
  UserState.msg
  HeadPostureState.msg
)

generate_messages(
  DEPENDENCIES
  std_msgs
)

catkin_package(
  CATKIN_DEPENDS rospy std_msgs opencv_apps message_runtime
)
```

Build and verify:

```bash
cd ~/catkin_ws
catkin_make
source devel/setup.bash
rosmsg show rchomeedu_vision/UserState
rosmsg show rchomeedu_vision/HeadPostureState
```

Expected:

```text
bool user_present
int32 consecutive_eyes_missing
int32 consecutive_face_absent
time stamp
```

Expected `HeadPostureState`:

```text
bool pose_visible
bool calibrated
bool head_down
float32 posture_score
float32 head_drop_ratio
float32 baseline_ratio
int32 consecutive_droop_frames
time stamp
```

## 7. Topic Parameters

`user_state_monitor.launch` is the only launch file for this module. It exposes two args:

```text

state_topic default /vision_and_presence_detection
```

Default run:

```bash
roslaunch rchomeedu_vision user_state_monitor.launch
```

Override if Member 1 chooses another topic:

```bash
roslaunch rchomeedu_vision user_state_monitor.launch state_topic:=/vision_and_presence_detection
rosrun rchomeedu_vision user_state_monitor.py --print _state_topic:=/vision_and_presence_detection
```

## 10. Acceptance Test

| Scenario | Expected output on `/vision_and_presence_detection` |
|---|---|
| Face and eyes visible | `user_present=True`, both counters 0 |
| Face visible but eyes missing | `user_present=True`, `consecutive_eyes_missing` increases |
| No face visible | `user_present=False`, `consecutive_face_absent` increases |
| User returns with eyes visible | both counters reset to 0 |
| Eyes missing then face absent | `consecutive_eyes_missing` is preserved while `consecutive_face_absent` increases |

| Phase 8 posture scenario | Expected output on `/head_posture_state` |
|---|---|
| Pose landmarks visible during calibration | `pose_visible=True`, `calibrated=False` |
| Calibration complete and posture upright | `calibrated=True`, `head_down=False`, low `posture_score` |
| Sustained head droop | `head_down=True`, elevated `posture_score`, `consecutive_droop_frames` increases |
| Pose landmarks missing | `pose_visible=False`, fatigue monitor should not treat it as normal posture |

## 11. Boundary

This module does not use `SoundClient`.

Speech belongs to fatigue/intervention/session modules. This module only publishes visual evidence.
